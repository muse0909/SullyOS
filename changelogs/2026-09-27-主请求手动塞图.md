## 踩坑 / 需要知道的（重要）
- **严格二选一成立**：开关关闭 → 手动塞图 + 不调识别 API；开关开启 → 走识别 API + 不手动塞图
- **临时缓存降级**：URL 没在缓存里 → 跳过手动塞图，主请求不带图（用户感知：图发出去但主模型没看到图，这是临时缓存失效的可见信号）
- **Gemini 协议自动适配**：手动塞的数组 content 进 Gemini 主请求体的"数组分支"自动转 inline_data parts，不需要额外改 Gemini 协议
- **base64 兜底场景**（图床全失败时 DB 直接存 data URL）：手动塞图也能用，直接拿 data URL 当 base64
- **主请求完成后清理**：line 2207 之后清理，正常路径上数据已发出
- **异常路径兜底**：fetch 抛异常时不会清缓存，靠 TTL 5 分钟过期兜底（异常罕见，主请求失败用户会重试）
- **不动文件**：

  - MessageItem.tsx（第三件才加折叠标签）
  - chatPrompts.ts（不动）
  - Settings.tsx（第二步已加开关）
