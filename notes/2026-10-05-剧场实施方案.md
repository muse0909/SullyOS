### 两种看的方式（这版的核心）

| 方式 | 电脑要开着吗 | 什么时候用 |
|---|---|---|
| **在线看** | ✅ 要 | 刚搜到的新片，没下过 |
| **存到手机再看** | ❌ **不用** | 存过之后随时随地看，不挑网络 |

**「存到手机」流程**（暮色 10-05 15:41 定的核心）：

```
App 里点「存到手机」
   ↓
转发服务 → 短剧库：把这几集下了（短剧库下到 Mac 上）
   ↓
转发服务 → App：推给手机，手机存进本地
   ↓
App 显示进度：「正在存 第3集/39集…」
   ↓
存完 → 手机上直接播，电脑可以关了
```

> ⚠️ **下载那几分钟电脑要开着，存完之后就不用。**
> 这跟「不依赖电脑一直开着」不矛盾——**电脑只在下东西的那一刻需要**。
> 实测一集 10MB 大概 3 秒，一部 39 集两三分钟。

> **实测已确认**：`POST /api/ui/download`（格式 `{"ids":[...],"quality":0}`）
> **裸请求直接能调**，身份检查一下就过，不需要改短剧库。
> `GET /api/ui/tasks` 能拿到完整下载任务列表（含集数、进度、时长）。

**设计要点**：App 点下载后**不要一直挂着等**。转发服务记下要哪几集，
短剧库在后台下，App 定期问「好了没」。这样中途切出去也不会断。

## 1.5 手机本地存的剧，怎么跟短剧库的剧区分

App 里要记清楚每个片子**从哪来**：

| 来源 | 标记 | 断了网能看吗 |
|---|---|---|
| 短剧库已下载，存到手机的 | 「已存 39 集」 | ✅ |
| 用户上传的 | 「我的上传」 | ✅ |
| 短剧库在线的，没存 | 「未存」 | ❌ 灰色提示要连电脑 |

**别搞混**：同一个片子可能既在短剧库又有本地份，App 要以**本地那份优先**，
不然用户点了发现还在连电脑，白等。

## 2. 核心机制：怎么"注入"主聊天

**照搬陪伴模式，不用任何开关、不用塞系统提示。**

陪伴模式的写法（`apps/DateApp.tsx:307` / `:409`）：
```ts
DB.saveMessage({ charId: char.id, role: 'user', content: text,
                 metadata: { source: 'date' } });
```

剧场照抄，把标记换成 `source: 'theater'`：

| 做什么 | 怎么实现 |
|---|---|
| 存一条 | `DB.saveMessage({ charId, role, content, metadata: { source: 'theater' } })` |
| 主聊天能看到 | 主聊天读消息**不过滤** source → 天然接上，**不需要"同步"动作** |
| 剧场自己只看到自己的 | 读的时候过滤 `m.metadata?.source === 'theater'`（照 `DateApp.tsx:413`） |
| 人设 | 进场时拿当前角色卡塞进 live 的 `systemInstruction` |
| 记忆 | 进场时把记忆宫殿相关摘要塞进 `systemInstruction` |

⚠️ **和共读那套不一样**。共读是"浮窗开着就把章节正文塞进系统提示"，
陪伴模式是"写进同一张消息表"。**剧场要的是后者**，上一轮我搞错了。

## 3. 自动重连：你什么都不用管

**live 有一对消息专门干这个：**

- 服务端发 `sessionResumptionUpdate` → 里面有个**恢复码**（`token`）
- 断了之后重连时带上 `sessionResumption: { handle: 那个码 }` → **聊天内容还在**
- 服务端要断之前会发 `goAway`（带还剩多少秒）→ 我们可以在它断之前**悄悄重连好**

**所以：**
- 会话**一直开着，不关**
- 每集播完 → 顺口问一句"刚才这集讲了什么，100 字以内" → 存起来 → 接着看下一集
- 断了自动重连，**全程无感，不弹任何东西**

⚠️ **诚实说明恢复的边界**：
- 恢复的是**对话上下文**（聊了什么）
- **正在流的视频帧不会恢复**（那是流不是状态）——重连后重新开始发帧
- 重连有几百毫秒到一两秒的空档，**聊天区要显示"重连中…"的小字**，别装没事

### 第 0 步：Mac 转发服务（不碰 App，先在电脑浏览器里验）

写一个几百行的小服务放桌面，端口 8999。**短剧库一个字不改。**

它干四件事：
1. 启动时向短剧库要一次身份（cookie + 身份码），**自己存着**
2. `/drama/list` — 转发"已下载"列表
3. `/drama/search` — 转发联网搜片源
4. `/video/stream` — 转发视频流，**并且加上手机能读的响应头**

**这一步最关键的不是功能，是那三个响应头**：

| 头 | 为什么必须 |
|---|---|
| `Access-Control-Allow-Origin` | 不加，视频画到画布上读不出像素，**模型永远看不见画面** |
| `Access-Control-Allow-Private-Network: true` | 不加，手机弹"是否允许访问本地网络"或直接拦 |
| 支持 `Range` 请求 | 不支持就没法拖进度条 |

**✅ 怎么验证**
1. 电脑上开浏览器访问 `http://127.0.0.1:8999/drama/list` → 看到 6 部剧、39 集
2. **手机浏览器**（先不用 App）访问 `http://<Mac的IP>:8999/video/stream?...` → **能播**
3. 手机浏览器控制台里执行 `document.querySelector('video')` 取一帧画到 canvas 再 `getImageData` → **不报安全错**（这条过了，App 里就一定过）

> ⚠️ 第 3 条是整个功能的命门。**过不了就是做不成**，先验证它。

### 转发服务做了哪几件关键的事

1. **剥掉浏览器的来源头再转发** —— 短剧库 `playbackRequestAllowed` 会检查
   `Sec-Fetch-Site` 只能是 `same-origin`/`none`，`Origin` 必须同源，带跨站值直接 403。
   手机是跨站请求，必被拦。转发服务把 `Origin`/`Sec-Fetch-Site`/`Referer` 全部剥掉再发。
   验证：带 `Sec-Fetch-Site: cross-site` + 跨站 `Origin` 请求，返回的不是 403 而是正常数据。
2. **把 `Cross-Origin-Resource-Policy: same-origin` 删掉** —— 短剧库自己会设这个头。
   **不改的话手机上画布一定被污染，`getImageData` 直接抛错**，这是命门里最阴的一层。
3. **Range 原样透传**，上游给 206 就跟着 206，不给就整段给。
4. **自动持有身份** —— 启动时调一次 `/api/ui/viewer` 领 cookie，之后所有请求自动带上。
   遇到 401/403 会重领一次再试（短剧库重启会换签名密钥，旧 cookie 会失效）。
5. **只放行 `/api/ui/` 和 `/api/emby/` 开头的路径**，别让本机变成开放代理。

### 架构上改了一处（比原方案好）

原方案是"已下载的剧也走短剧库的播放会话"。实测发现那条路很绕：
已下载的集要用 `taskId` 开会话，会话里还得先"选集"才能播，返回 409「请先选择要播放的分集」；
而用 `dramaId` 走在线播是转码模式（`X-Playback-Mode: transcode`），
**直接吐 48MB 全量、彻底忽略 Range**，拖进度条会很难受。

改成：**已下载的集直接读磁盘文件**（`/relay/local/video?drama=仙君他断情绝爱&episode=1`），
原生的 Range 支持，拖动秒响应。实测三种 Range 全对：

```
Range: bytes=0-1048575   → 206  bytes 0-1048575/10030651
Range: bytes=8388608-    → 206  bytes 8388608-10030650/10030651
Range: bytes=-100        → 206  bytes 10030551-10030650/10030651
```

短剧库的播放会话只在"看没下载的集"时才用。

### 接口参数备忘（踩过的坑）

- dramaId 格式是 `hongguo:7691205405866724414`，**不是剧名**。
- `POST /api/ui/playback/open` → 返回 `session` 字段。
- `GET /api/ui/playback/stream` **必须带 `session` + `episode` + `start`**，少一个都是
  410「播放会话已过期」或 400「集数或播放位置无效」。这三个参数是分三次才摸对的。

### 写这个时犯的错

- **列数样式取名 `.c3`/`.c4`，跟原型里占位封面的底色类重名**，整块网格糊了一层紫底/黄底。
  截图才看出来。→ App 里写样式别用太短的名字。
- **路由判断用了拼了查询串的字符串**（`/relay/local/video?drama=xxx` ≠ `/relay/local/video`），
  带参数就匹配不上，返回 404。→ 路由匹配必须用 `urlsplit().path`，不能用拼了 query 的串。

## 10. App 里连不上电脑：https 页面不许取 http（10-05 17:30）

### 现象

- 手机浏览器打开 `http://192.168.0.102:8999/frame-test.html` → **四项全绿**
- 手机打开 App（或浏览器打开 `https://...vercel.app`）→ 点「连一下」→ `Failed to fetch`

### 原因：混合内容（mixed content）

页面自己的地址是 `https`（Vercel），要去取的资源是 `http`（电脑的转发服务），
**Chromium 直接拦下**。手机浏览器和 App 里的 WebView 都受这条管。

第 0 步在浏览器里测通，是因为那个页面的源**本身就是 http**，同源，不算混合内容。
**同一个东西，两套规则 —— 我只测了一种就当成了结论，这是这次真正的盲点。**

源码依据（`node_modules/@capacitor/android/.../Bridge.java:569`）：

```java
if (this.config.isMixedContentAllowed()) {
    settings.setMixedContentMode(WebSettings.MIXED_CONTENT_ALWAYS_ALLOW);
}
```

Capacitor **只在这个开关为真时才放行**，默认不放行。字段名是 `allowMixedContent`。

### 解法

1. `capacitor.config.json` 和 `capacitor.config.test.json` 都加 `"allowMixedContent": true`
2. **必须重新打包 apk** —— 这个值在 App 启动时从 assets 里读，远程加载改不了
3. 两份配置都要改：gradle 的 `syncCapacitorConfig` 会按 `-PtestBuild` 选其中一份，
   漏了哪份就装上旧行为

### 顺带修的：video 必须走跨源模式

`TheaterApp.tsx` 的 `<video>` 加了 `crossOrigin="anonymous"`。
不写的话这个 video 是「不带 CORS 的跨源加载」，**第 3 步画到 canvas 上会被判脏数据，
`getImageData` 直接抛 SecurityError** —— 角色就永远看不到画面。
写成 anonymous 走 CORS 加载就不脏，转发服务那边已经带了 `Allow-Origin` 头，两边配对。

**这条要跟 `allowMixedContent` 一起上**：单独设 crossorigin 的话，
CORS 加载属于「主动混合内容」，反而更容易被拦。

### 教训（以后每次都照着做）

- **手机浏览器测通 ≠ App 里能通**。App 的页面源协议、加载方式跟浏览器不同，
  跨设备验证必须在 App 的真实条件下做，浏览器只能当粗筛。
- 任何「https 页面 + http 资源」的组合先在脑子里过一遍。
