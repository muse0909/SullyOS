# 剧场：让它自己开口（触发方式换了）+ 集末问句只问一次 + 记录卡加向量化

**日期**：2026-10-08
**涉及 commit**：`dc76c623`

## 改了什么

### ① 主动说剧情失败 —— 换了触发方式（暮色 19:17「没有主动说剧情，只有问了才说」）

**病根**：`activityStart` / `activityEnd` 真机上**一点用都没有**，而且不报错。

这两个字段是实时协议里标记「一段输入开始/结束」的，本来就是给这个场景用的。
但协议有个坑：**服务端不认识的字段是静默忽略、不报错**的（`sendFrame` 那条注释
已经吃过一次亏 —— 写 `mediaChunks` 时画面就是不来，也不报任何错）。
所以现象是「催了没用，它还是不说话」，一点线索都没有 —— 既可能压根没收到，
也可能收到了但自己选择不说话。**这两种情况从外面看一模一样。**

**做法**：退回 `clientContent` 硬问一句。这是**唯一确定能让它回话**的通道
——主聊天每一句都是这么走的，它回了就一定有下文。

代价有两个，都在代码里处理掉了：

| 代价 | 怎么处理的 |
|---|---|
| 它**一定回，没法真的闭嘴** | 「画面没变化就闭嘴」改在**代码里**判：`grab()` 里画面跟前一张差不多就压根不送，也就走不到问的那一步 |
| 会**打断**它正在说的话 | `nudgeScene` 里 `if (this.speaking) return false`，不发 |
| 每问一次历史里多一轮对话 | 可接受 —— 而且这正是要的效果：上下文里有它自己上一句，剧情天然串起来 |

**为什么不用 `pushUserTurn`**：它会打断（清 `speaking`），还会写 `lastUserTurnAt`
—— 那个字段是「刚刚有人说过话」的时间戳，用来识别「它自己憋不住开口」
（`flushText` 里的 SPONT 现场记录）。催一次写一次，这个诊断**永远是 -1**，等于废了。

**频率：8 秒 → 20 秒**。8 秒是**按老的触发方式定的**，那时候模型压根不理，
这个数形同虚设。换成确定能回话之后，每催一次就是实打实一句模型的话 ——
8 秒一集能出十几句，聊天框直接刷爆。现在一集三四句，是「随口搭一嘴」的密度。

再加两道闸：

- 它刚说完那 6 秒内不催（只判 `isSpeaking` 不够：它答完时 `speaking` 立刻空了，
  但那句往往还有 2~3 秒才说完，这时候再塞一句等于把它刚讲的截断重来）
- **你刚发话 8 秒内不催**（你问了一句正等回答，这时插一句「画面往前走了一步」，
  两轮问答叠着发，模型会以为要一起回答）

### ② 集末问句重复四遍 —— 根因在播放器，不在发的地方

**病根**：`ended` **不是一个剧集只来一次**。实测它会连着来三四遍：

- 自动连播已经调了 `playEpisode(next)`，新剧集还没解码出来，
  `currentTime` 还杵在上一集的结尾 → 又触发一次
- 在线流（MediaSource）播完时缓冲尾巴还会再补一发
- 换 src 时旧 src 的结尾也会补一发

每触发一次就排一个 3 秒的定时器，四次就是**四句话排队发出去**，
模型对着同一句答四遍 —— 屏幕上就是同一句问四遍、答四遍。

**三道闸**：

1. **`PlayerStage.endedFired`（治根，在源头）**：一次播放只认第一次 `ended`。
   新剧集的 `onLoadedMetadata` / `onPlay` 里清零，下一集照样能报结束。
2. **`TheaterApp.onEnded`（按集号）**：键是 `剧名#集号`，
   所以「同一集重播」不会被误挡；顺手把上一个没发出去的定时器收掉。
3. **`useTheaterLive.askWrapup`（兜底）**：15 秒内不问第二次。

前两道都在新的那一轮开始时（进播放页）清零 —— 不然「上一轮看过第 3 集」
会把这一轮的第 3 集也挡掉。

### ③ 剧场记录卡底部加「向量化」按钮

暮色原话：「卡片我想在最底下增加一个向量化的按钮。把卡片里的内容发给模型
总结成向量化记忆。」

新文件 `utils/dramaTheater/vectorizeRecord.ts`：

1. **先总结**：把卡片正文（两个人的对话原文）发给模型，压成 1~4 条「发生了什么」
2. **再向量化**：拼成 `MemoryNode` → `vectorizeAndStore` 存进记忆宫殿

**为什么不能把原文直接丢进去算向量**：向量是拿整段文字算的，一段对白算出来的是
「这段话的整体语气」，不是「他们一起看剧时提到了小师妹」这种具体的事 ——
以后聊天问起相关的事，相似度上不来，召不回来。而且对白里有一堆「嗯」「对」
这种噪音。

**用的哪套模型**：

- 总结：优先记忆宫殿的**副模型**（轻量快），没配就退回主聊天那套
  —— 跟 `useTheaterLive.runMemoryPost` 一个口径
- 算向量：只能用记忆宫殿的向量配置，没有第二个选择

**按钮位置**：卡片**外面**、展开区下面 —— 卡片折叠着也点得到，
不用「必须先展开才看得见按钮」多走一步。胶囊、浅紫、居中（AGENTS.md §5.3）。

## 踩坑 / 需要知道的（重要）

### ⚠️ `handleVectorize` 的位置不能随便放（差点踩 TDZ）

它要用 `displayContent`，而 `displayContent` 在组件中段才算是 const。
写在组件顶上 = 每次渲染 `ReferenceError` = 整个聊天页白屏。
本项目同款事故炸过三次（07-31 / 08-01 / 10-07）。

**但也不能写在太后面**：下面有个 `if (!displayContent && !hasVoiceContent) return null`，
钩子写在它后面就会「消息条数一变、钩子数量跟着变」，React 直接报错。

**规矩**：放在 `displayContent` 之后、所有提前 return 之前。
现在的行号：1735 定义 → 1761 钩子 → 1804 提前 return。

### ⚠️ `MessageItem` 是 `React.memo` 包着的

handler 不能在渲染里顺手 new 一个传给子组件（每次 render 新函数 →
卡片整棵重渲染）。用了 `useCallback` 固定。

### ⚠️ `nudgeScene` 不能碰 `lastUserTurnAt`

那个字段是「刚刚有人说过话」的时间戳，`flushText` 靠它识别
「模型自己憋不住开口」（>5 秒没收到用户输入就自己说了 → 记一条 SPONT）。
写一次就永远失效，等于把现场记录废了。

### 顺带记一笔：`ended` 会连着触发，这不只是剧场的问题

任何用 `<video>` + 自动连播的地方都可能有。`PlayerStage` 里那个
`endedFired` 是治根的判据，别以后「优化」时又去掉。
