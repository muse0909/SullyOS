## 1. 短剧库那道门：只防浏览器，不防后端

短剧库的播放接口有三层防护（`internal/app/ui_playback.go:97` 的 `playbackRequestAllowed`）：

| 层 | 检查什么 | 浏览器发不发这个头 |
|---|---|---|
| 1 | `Sec-Fetch-Site` 必须是 `same-origin` / `none` | **发**（浏览器自动加） |
| 2 | `Origin` 头必须为空或同主机 | **发** |
| 3 | 响应带 `Cross-Origin-Resource-Policy: same-origin` | 浏览器强制执行 |

还有身份层：cookie（HMAC 签名）+ `X-Juku-Viewer` 头必须跟服务端算出来的一致 + 播放会话必须属于这个身份。

### 实测结果（今天在 Mac 上真跑的）

一条最普通的网络请求，**不带任何浏览器标记**：

```
1) GET  /api/ui/viewer            → 200，拿到身份 id
2) POST /api/ui/playback/open     → 200，拿到 session
3) GET  /api/ui/playback/stream   → 200，真视频流
```

第 3 步的响应头：
```
Content-Type: video/mp4
X-Playback-Duration: 460.330          ← 7 分 40 秒
X-Playback-Mode: transcode
Transfer-Encoding: chunked
```
落到本地 **57,114,337 字节**，文件头 `0000 001c 6674 7970 6973 6f35`（`ftypiso5`，标准 MP4）。

**为什么裸请求能过**：`Sec-Fetch-Site` 和 `Origin` 都是**浏览器自动加的头**，
后端 HTTP 客户端压根不发。第 1、2 层走 `case "":` 直接放行。
第 3 层（CORP）浏览器强制执行——所以**后端能过，网页里的 `<video>` 不能**。

### 结论

**改短剧库是不必要的。** 只要取流的那一端不是浏览器，就绕开了全部跨站防护。
（这层防护的本意是防盗链，不是防自家 App，作者没料到会有人从后端取。）

⚠️ **但这是「用后端绕过」的路子，不是「打开大门」的路子。** 如果短剧库以后加了
「必须带某个签名 token」或者 IP 白名单，这条路就断了。做之前要跟暮色说清楚。

## 2. 手机端要过三道浏览器关卡（都能解，但要真机实测）

App 页面在 `https://sully-muse-vert.vercel.app`（加密），视频流在 `http://192.168.x.x:端口`（局域网明文）。
以下三道是**网页里直接取流**才会遇到的，Mac 上加个转发服务就能全解：

| 关卡 | 现象 | 解法 |
|---|---|---|
| 混合内容 | 加密页面拉明文资源，Android 9+ 默认拦 | `capacitor.config.json` 里 `cleartext: true` 已开，**但要真机实测** |
| 私有网络访问 | 公网页面访问局域网地址，浏览器要弹授权 | 转发服务回 `Access-Control-Allow-Private-Network: true` |
| 跨域读画面 | 视频地址不允许跨域 → 画布被「污染」→ `getImageData` 抛错 | 转发服务回 `Access-Control-Allow-Origin: <拾光机地址>`，App 侧 `video.crossOrigin = 'anonymous'` |

**第 3 条是硬门槛**：不同源的视频画到画布上就读不出像素，模型永远看不到画面。
所以「手机直接连 Mac 短剧库」这条路**走不通**，中间**必须有一个 Mac 侧的转发服务**。

**好消息**：SullyOS 里 `drawImage` + `getImageData` 的成熟写法早就有了
（`apps/pixelHome/PixelRoomEditor.tsx:254`、`PixelAssetGenerator.tsx:101`），暮色认这种代码。

## 4. live 模型能不能吃一整集

**模型是 `gemini-3.8-live`**（2026 年 9 月更新的稳定版，不是我一开始搜到的 2.0 / 2.5 旧款）。

| 项目 | 值 |
|---|---|
| 输入 | 文字、图片、**音频**、**视频** |
| 输出 | 文字 + 音频 |
| 输入上限 | 131,072 |
| 输出上限 | 65,536 |
| 函数调用 | 支持 |
| 缓存 | **不支持**（顺带把「live 走缓存」这条路也排除了） |
| 视频帧率 | **最高 1 帧/秒**（官方写死） |
| 默认行为 | `TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO` —— **视频帧默认就全发给模型** |

**所以「发视频」不用做任何特殊配置**，连上就一直在发。

### 上下文撑爆：官方给了解法，但只解了一半

`BidiGenerateContentSetup` 里有 `contextWindowCompression`：

- `slidingWindow` —— 滑动窗口，旧的自动滑出去
- `triggerTokens` —— 到多少 token 才触发（默认是上限的 80%）

**这意味着会话可以一直开着不撑爆。** 但——

⚠️ **滑出去的内容是真的没了。** 压缩是为了「能一直聊下去」，
**不是**为了「一集剧看完全记住」。滑掉的部分，模型后面就真的不记得了。

### 结论

- ✅ **边看边聊** = 真发视频帧 + 真发麦克风声音，**默认就是全视频输入**，能做到
- ❌ **「看完一整集记住全部剧情」** = **还是做不到**。滑动窗口救不了——它只保「不崩」，不保「不忘」。

**这条不变，还是需要暮色拍板「看完记什么」。**

### 顺带：live 能拿到真实用量

返回消息里**有 `usageMetadata` 字段**。这比现在聊天那条链路强——
中转站只给字符长度，不给真实账单；live 直接给 token 用量。

### 顺带标一条不推荐的路

短剧库有弹幕接口（`/api/ui/playback/danmaku`），但：
- 刚才试的那一集**不支持**（黄豆源没这数据）
- 弹幕是**观众的话**，不是对白，不是字幕
- 拿它当剧情用 = 把噪声当事实

**明确标出来是为了以后别有人再走一遍。**

## 5. 接入方式：直连官方，不经过中转站

> ⚠️ 本节初版写的是「必须问站长支不支持长连接」——**那是错的，见第 9 节。**

Live API 走的是 **Google 自己的地址**，跟中转站完全没关系：

```
wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?key=API_KEY
```

**SullyOS 里已经有 Gemini 直连的先例**（2026-07-27 做过「主 API / 识图 / 生图」三通道直连，
见 `changelogs/2026-07-27-gemini-direct-connect.md`），所以这条路是走通过的。
**免费、没有限量**（暮色原话）。

### 两种鉴权方式

| 方式 | 怎么做 | 密钥安全 |
|---|---|---|
| **直接用 key** | `?key=API_KEY` | 跟现在 SullyOS 存聊天 key 一样，**存在手机本地** |
| **临时令牌** | 后端 `POST /v1beta/auth_tokens` 换一个短命 token，客户端当 key 用 | 短命（30 分钟）、只能用一次开会话 |

⚠️ **临时令牌有几个容易踩的点**：
- 只能用 `v1beta`，且**只对 Live API 有效**
- 端点要换成 `BidiGenerateContentConstrained?access_token=TOKEN`（**名字不一样**）
- token **1 分钟内必须用来开会话**，开会话后连接能撑 30 分钟
- 超过 10 分钟要靠「会话恢复」重连（同一个 token 可以，`uses:1` 只算开会话那一次）
- 可以把**模型和系统提示词锁在 token 里**（`liveConnectConstraints`），客户端拿不到

**如果用临时令牌，还是需要一个后端**——但那只是一个「换 token」的一次性请求，
**不是长连接代理**。Vercel Functions 做这个绰绰有余（它做不了长连接代理，但这个不需要）。

**按现状（SullyOS 所有 key 都存本地）走直接用 key 最简单，跟现有做法一致。**
用不用临时令牌，是暮色要选的——选临时令牌多一层安全性，代价是多一个 Vercel 接口。

## 8. 踩坑 / 记住的点

- **判断「能不能拿到数据」不要看代码里写了什么限制，要看那个限制依赖的头谁来发。**
  这次差点因为「有三层跨站防护」就下结论说做不了——实际上那三个头全是浏览器自动加的，
  后端一发都不发。**防护强度取决于对手是谁，不是取决于代码有几层。**
- 短剧库的身份不是登录态，是 **HMAC 签名的 cookie**（`ui_viewer.go` 的 `identity()`，
  签名过期时间 1 年）。要伪造很容易——所以它的「防盗链」本来就不是防伪造的，
  是防「别人的网页偷偷嵌你的播放器」。**我们不属于那个威胁模型。**
- 弹幕 ≠ 字幕 ≠ 对白。以后再看到「有弹幕接口」别当剧情源。
- **`gemini-3.8-live` 不支持缓存**。以后别想在 live 这条链上省 token。
