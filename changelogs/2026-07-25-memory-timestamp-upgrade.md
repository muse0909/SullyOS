# 记忆宫殿时间戳升级「日期+时分+距今多久+智能时段」

**日期**：2026-07-25  
**涉及 commit**：`8645ce1`

## 改了什么
- `utils/memoryPalace/formatter.ts` 加 `formatMemoryTimestamp(ts)` helper
- 4 处替换：独立记忆 / 事件盒 summary / 事件盒活节点 / 便利贴置顶
- 之前：`(2026/7/24, 重要性: 7)`
- 现在：`(2026/7/24 22:30 · 1天前晚间, 重要性: 7)`

## 改之前的问题（暮色 7/25 反馈）
- 昨晚（7/24 22:00）跟 Sully 聊的，今早（7/25 13:00）再聊，Sully 写"今晚"
- 根因：formatter 只输出日期，AI 跟"当前时间 7/25"对比不会主动换算
- LLM 又字面复读 memory 里的"今晚"二字 → 死循环：新对话又写"今晚" → 新 memory 又存"今晚"

## 输出粒度
- 60 分钟内：`X分钟前` + 时段（刚刚/上午/下午...）
- 24 小时内：`X小时前` + 时段
- 30 天内：`X天前` + 时段
- 30 天以上：`X个月前` + 时段

时段映射（本地时）：
- 0-4 凌晨 / 5-7 早晨 / 8-11 上午 / 12-13 中午 / 14-17 下午 / 18-19 傍晚 / 20-22 晚上 / 23+ 深夜

## 动了哪些文件
- `utils/memoryPalace/formatter.ts` — 加 helper + 替换 4 处日期格式化

## 踩坑 / 需要知道的（重要）
- **Token 增长**：每个 memory 大约多 20 字符，15 条 memory 多 300 字符约 150 token。可接受。
- **没改存储格式**：MemoryNode.createdAt 还是 unix ms（Date.now()），只改**注入到 prompt 的渲染格式**。下次 extraction 阶段如果需要按新时间筛选（"近 1 天"等），底层数据够用。
- **没修死循环的"输入端"**：AI 这次写对话时如果又写"今晚" → memory 提取时还是会保留"今晚"。要彻底切断死循环需要改 extraction prompt 让 LLM 规范化时间词——但这是大改，先观察这版效果。
- **没改 `RetimeContextManager` 的"当前时间"段**：那段本身输出 `2026年7月25日 周六 下午 13:43` 已经清晰，AI 知道"现在"是几号几点。

## 备注
- 预期效果：暮色 7/25 再跟 Sully 聊，Sully 检索到 7/24 22:30 的 memory 时，看到 "1天前晚间" 就不会把字面"今晚"搬到 7/25 的现在
- 观察点：如果还偶尔说"今晚"，可能是 extraction prompt 的事，再考虑方案 B（让提取 LLM 规范化时间词）
