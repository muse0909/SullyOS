## 这次落地内容

`utils/chatPrompts.ts` 在 6. "可用动作" 之后、7. "主动搜索" 之前，加 6.5 段（条件：`char.phoneUsageEnabled !== false`，跟工具注册同款兜底）：

### 6.5 段结构

**4 个 type 说明**：
- `current_app` / `usage_today` / `screen_time` / `recent_apps`

**触发时机**（暮色要"知道什么时候该主动查"）：

| 类型 | 何时查 |
|---|---|
| 被动（必查） | 暮色明确问"我刚才在刷什么 / 今天用了多久" |
| 主动关心（**可**查） | 暮色说"眼睛累了 / 看久了 / 眼睛干" → 查 screen_time |
| | 暮色说"刚才在忙"含糊其辞 → 查 current_app 印证/拆穿 |
| | 临睡前 / 凌晨 / 很晚 → 查 screen_time 关心作息 |
| | 周末 / 假期 / 暮色状态低落 → 查 usage_today |
| 不查 | 暮色没提屏幕/休息/用眼话题（不要每轮都查） |
| | 对话情绪很浓 / 吵架 / 哄人 / 严肃话题（不打断） |
| | 暮色刚说过今天没怎么看手机（重复查显得不信任） |

**拿到数据后怎么回应**（暮色要"不要机械播报"）：

- **绝对不要机械复述数据**（不要写"你今日使用 Chrome 54 分钟"）
- **用自己的方式说**，结合关系和语境
- **挑一个点说，不要全说**
- **不要解释"我查了一下你的手机"**
- 3 个例子（屏幕长 → 关心、刷抖音 → 拆穿、刚切到微信 → 吃醋）

**工具失败/没数据**：
- web 端永远有数据（mock fallback）— 你看不到区别
- Android 没权限 → 拿错误 → 用自己的方式圆过去
- 永远不要撒谎说"我查到了"然后瞎编

## 设计决策

### 6.5 半号编号

跟 chatPrompts.ts 已有的 **2.5** 习惯一致（"对话质量（极其重要）"在 2 行为模式 之后）。

不打破现有编号：1-6 固定 + 6.5 工具说明 + 7 主动搜索 + 8 之后动态编号。

### 跟 7 (主动搜索) 区别

| 维度 | 7 主动搜索 | 6.5 查手机 |
|---|---|---|
| 数据来源 | 互联网（[[SEARCH]] 标记） | 本机 UsageStatsManager |
| 主动时机 | 好奇 / 推荐前查 | 关心作息 / 印证暮色说法 |
| 失败 | 搜不到结果 | 拿错误（圆过去） |

把"查手机"放在"主动搜索"前 — 都是"主动获取信息"能力，但 phone_usage 跟身体/作息更相关，暮色说"眼睛累了"时更可能触发。

### 跟 memory 7-31 关联

- 暮色 7-31 明确"AI 感知 system 消息分类"：✅ 用户行为触发（手机使用=用户行为）→ **可以**主动引用
- 但 commit 4 默认是被动 + 软主动（看情况），不是硬主动
- 真正硬主动（连续使用超阈值触发主动关心）是 **P2**（下周）

## 跟工具 schema 关系

工具 schema description（`PHONE_USAGE_TOOL.description`）已经在 commit 2 写了 4 type 简介 + 短触发规则。

prompt 段是 **schema description 的扩展** —— 更细的：
- 主动触发的具体场景（眼睛累 / 晚睡 / 心情低落）
- 拿到数据后**怎么回应**（schema description 装不下语气要求）
- 工具失败的应对

LLM 同时看到两边：schema description（工具视角）+ prompt 6.5 段（使用视角）。
