## sync 2.0 step 3 续：调试面板入口（BuildBadge + DevDebugPanel + swVersion）

按暮色 9-15 12:19 拍板，上一轮 step C+D 把 Amsg2DebugPanel 接到了
App.tsx，但 SullyOS 缺上游的 BuildBadge + DevDebugPanel，导致调试面板
默认不显示（`enabled = readDevDebugFlags().amsg2Panel` 默认 false，
且没法手动开 flag）。

本轮补 3 个文件 + 1 处类型声明。

**3 个 SullyOS 缺的上游文件整文件从 upstream/master HEAD (27987fbb) 复制：**

| 文件 | upstream 行数 | 干什么 |
|---|---|---|
| `utils/swVersion.ts` | 58 | 通过 MessageChannel + postMessage GET_SW_VERSION 协议向 SW 询问版本，1.5s 超时兜底（BuildBadge / VersionInfo 都复用）|
| `components/BuildBadge.tsx` | 95 | 右下角构建版本指示器：阶梯式三行（sw@xxx / branch@shortHash / 开发中内容），连点 5 下触发 unlockDevDebug() |
| `components/DevDebugPanel.tsx` | 559 | Dev 调试面板（amsg2Panel / lifecycle capture / memory log / blob gc / 手动 unlock 等开关）|

**`App.tsx` 接入：**
- 加 `import BuildBadge / DevDebugPanel`
- 在 OSProvider 外层挂 `<BuildBadge />` 和 `<DevDebugPanel />`（upstream App.tsx 同款位置）

**`vite-env.d.ts` 补全局类型声明：**
- `declare const __BUILD_BRANCH__: string;` 等 4 个常量
- vite.config.ts 的 `define` 在 build 时替换，但 TS 编译需要类型声明
  才能识别这些全局常量。这次顺手把 buildInfo.ts / devDebug.ts / BuildBadge.tsx /
  DevDebugPanel.tsx 7 个 TS 错一起清掉

**摸底：**
- Vite build ✓ 4.45s
- tsc 错数 644 → 631（-13，__BUILD_* 7 错清零）

**使用方法：**
1. 打开 preview 任意页面，右下角看 BuildBadge（"sw@xxx / preview@xxx / 开发中内容"三行小标签）
2. 连点 BuildBadge 5 下 → 解锁 dev debug 面板
3. 在 DevDebugPanel 里找到 `amsg2Panel` 开关拨开 → Amsg2DebugPanel 显示
