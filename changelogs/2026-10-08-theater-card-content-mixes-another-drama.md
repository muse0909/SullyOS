# 主聊天的剧场卡片串内容：标题是这一部、正文是上一部

**日期**：2026-10-08
**涉及 commit**：`cf4b7b21`

## 改了什么

修「剧场记录卡片正文串场」。暮色 22:23 截图：卡片标题写的是
《花茶人偶苗疆少主他又争又抢第五季》第 1 集、开头也是「一起看完了《花茶人偶…》」，
但下面整段对话全是《剑宗小师妹》的旧内容（小师妹、食堂、敬酒、穿越、毛绒兔子系统）。

**病根：「这一轮」是按「位置」认的。**

原来 `finishTheaterSession` 里，「这一轮的话」＝ *库里最后一张剧场卡片之后的全部剧场消息*。
这个判据只在**每一场都成功写出卡片**的前提下才成立。
中间只要断一场（没写、写了但抛错、或者早期版本压根没这个功能），
后面每一场都会把之前所有积压的旧话一起吞进去 —— 卡片越写越长、越串越远。

**标题为什么看着是对的**：标题取的是 `seg` **最后一条消息**的剧名标记，
而那一轮确实在看花茶人偶。所以「标题对、正文错」正是这个 bug 的招牌。

⚠️ **昨天推的 `8a83c728`（一句没说也要写卡片）治不了这个。**
它只保证卡片不断档；一旦断过，积压的旧话已经进去了。
而且那一轮角色全程没说话时，它照样会把旧话当成这一轮的话写进卡片。

## 踩坑 / 需要知道的（重要）

### ① 标记只在「用户发过话」时才更新 —— 换剧后角色自己说的话全打错标签

原来 `tagRef.current = tag` 只写在 `send()` 里。
也就是说**「你在这一轮说过话」才会更新剧名**。

于是换剧之后，只要角色是**自己先开口**（10-08 才加的主动说剧情），
它说的每一句都还挂着**上一部剧**的标签。连带三处都错：

- 入库带着错的剧名
- 主聊天那条 `剧场 《xxx》` 小标签显示错的剧
- 灌给主聊天模型的上下文 `[剧场 《上一部》]` 是错的
- `theaterEpisodes` 收集号时会把上一部的集号混进来

`startFresh()` 里没清 tagRef 是同一件事的另一半，两边都补了。
**但那只是治标** —— 只要新剧里用户一直没说话，清 ref 也没用，
所以标记改成**现算**（每次问「现在在看哪部哪一集」）。

### ② 传给 `useTheaterLive` 的 `scene` 是个「永远停在开机那一刻」的函数

原来是内联箭头：

```ts
scene: () => ({ title: picked?.title || '', episode: currentEp, at: 0 })
```

它每次 render 都是**新函数**，闭包里锁的是**当次 render 的** `picked`。
而 `onText` / `saveModel` 这些回调是 **boot 时就交出去**的，之后不会再换 ——
它们问 `scene()` 拿到的永远是**建会话那会儿的剧**。

原来没炸出来，纯属侥幸：标记走的是 ref（ref 是活的，绕开了这个坑）。
现在标记改成现算 `scene()` 了，这个坑必须一起补，否则
「换剧后模型自己说的话」会被判成上一部剧 —— **比原来更糟**。

改法：`sceneRef` 每次 render 同步最新值，`scene` 是 `useCallback(..., [])` 的稳定引用。
⚠️ 写在 render 里而不是 effect 里：effect 要等 commit 之后才跑，
而 boot 是在 effect 里跑的，两者顺序一旦变化就会读到上一帧的值。
赋的是**幂等的派生值**，render 里同步是安全的。

**以后往 `useTheaterLive` 传任何「当前状态」的 getter，都得满足这两条：
稳定引用 + 永远读得到最新值。** 不然 boot 出去的闭包就废了。

### ③ 判断依据要跟着修一起改

`8a83c728` 那个「一句没说也要写卡片」的注释，写的是同一个症状、
归的是另一个原因（说「`seg` 是空的所以没写卡片」）。
不改正文的话，下一个人还会照着它往错方向查。已经把注释里那段现场描述
改成「22:23 又报同一个症状，但原因已经不是这个了」。
