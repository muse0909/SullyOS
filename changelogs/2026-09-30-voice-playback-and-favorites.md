# 语音留存：通话记录能回听 + 语音收藏自己存一份

**日期**：2026-09-30
**涉及 commit**：（见 git log，`fix/call-voice` 分支）

## 改了什么

暮色：「这个语音消息是存本地吗？我想保存下来，可不可以存个数据库里？以后随时能听，不用再调用模型重新生成？」
以及：「我之前在发现页里增加了一个语音收藏的功能，但是收藏的每次都是存不住，做了缓存但是也很快就失效了，如果这两个是一样的问题就一起查一下。」

### 一、通话语音真正存下来 + 能回听

- **新增 `utils/callAudioStore.ts`**：把「最终拿去播的那份 blob」存进 `assets` 表，键 `call_audio_<消息id>`。
- **`apps/CallApp.tsx`** 四条合成路径都存：Volink 回复、MiniMax 单块、MiniMax 分块合并、开场白（Volink + MiniMax 两条）；
  外加「换个说法」重合成时覆盖同一份。
- 存完把键写进消息的 `audioAssetKey`（`DB.updateMessageMetadata`）。
- **回放按需取**：点「重播语音」才去读 blob，不在打开记录时把几十条音频全读出来。

### 二、语音收藏改成自己存一份

- **`utils/favoritesStorage.ts`**：新增 `saveFavoriteVoiceBlob` / `getFavoriteVoiceBlobByFavId` / `deleteFavoriteVoiceBlob`，
  键 `fav_voice_<收藏id>`。**不再借用 Chat 的 `voice_msg_*`**。
- **`apps/FavoritesPage.tsx`**：播放走新路径（拿不到再回退借 Chat 的，兼容老数据）；
  三个删除入口（单删 / 批量删 / 清理失效）统一走新增的 `purgeFavorite()`，顺带清掉自己存的那份。
- **`components/chat/ChatModals.tsx`**：**补回语音收藏入口**（7-22 移除「语音自动加入收藏」时被一起删了）。
  进消息菜单时异步查这条消息有没有存过语音（聊天里语音是「点播放才生成」的，不能无脑显示按钮），
  有才显示「收藏语音」。

## 踩坑 / 需要知道的（重要）

### 1. 这俩不是同一个问题，但根子一样

- 通话回放：音频**早就存在库里**（`utils/ttsCache.ts`，而且是当初按要求故意不清缓存的），
  但消息没记住它在哪 → 找不到
- 语音收藏：收藏**只记了个引用**（`sourceMessageId`），没自己留底 → 借的那份没了就没了

共同点都是「文件在，但没人知道它在哪」。

### 2. 语音收藏的云端那条路从一开始就是死的

`getFavoriteVoiceCloudUrl` 指向 `/api/v1/voice-favorite-store`——**Netlify** 的路径。
项目早就搬到 Vercel，`api/v1/` 目录压根不存在，上传过去只有 404。
而且 2026-07-22 取消「语音自动加入收藏」时，Chat 里整段上传代码已被删除，现在收藏时**根本不会去上传**，`item.url` 自然是空的。

这次没去救云端（那属于跨设备同步的活儿，工作量大一截，要用 R2），代码里保留只为了将来接口搬过来时不用重写。
播放时它排在最前面但实际永远命中不了，会自动落到本地。

### 3. 为什么不用 TTS 缓存的键，而要自己存一份

三个理由：
1. TTS 缓存是**按内容哈希**的，长回复会被 `splitTextForTts` 切块后合并，合并出来的音频不对应任何单个哈希键，没法只记一个键指过去；
2. TTS 缓存那边的写入是 fire-and-forget（`saveCachedTts(...).catch()`）不 await，紧接着按键回读会时序错乱；
3. 各管各的更耐用——以后给 TTS 缓存加配额清理时，通话记录的回放不受影响。

代价是同一段音频存两份（TTS 缓存一份、`call_audio_*` 一份）。一段 5 秒的话约 100–300 KB。
键跟消息 id 绑定，所以「换个说法」重合成是**覆盖**同一份，不会越攒越多。

### 4. 存的是 blob 不是地址

`blob:` URL 是内存引用，刷新就没了，而且不能直接存进 IndexedDB。
存的是 Blob 本体 + 一个键，播放时再 `URL.createObjectURL()` 现造。

### 5. 顺手修了 4 个既有类型错误

`ChatModals` 里 `Message.id` 是数字、`FavoriteItem.sourceMessageId` 是字符串，
原来 2 处直接比较/赋值（TS2367 / TS2322）。补语音收藏时照抄了这个写法又多 2 处，
一并用 `String(...)` 修掉。

## 备注

- **老记录还是听不了**：改动之前存的通话消息里没有 `audioAssetKey`。
- **换音色不影响历史回听**：回放读的是库里那一份，跟当前音色设置无关。
- 语音只存**已经合成出来的**。用户说的话（麦克风录音）目前不存，只存 AI 的回复。
- TTS 缓存是「只进不出」的，攒久了会占地方。给设置加个「清理语音缓存 + 看占用」入口的事还没做。
- 云端同步（跨设备听历史语音）没做。
