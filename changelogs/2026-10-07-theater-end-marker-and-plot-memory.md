# 剧场：退出时写一条「一起看结束了」（治重进又刷一条）+ 剧情串不起来的真相

**日期**：2026-10-07
**涉及 commit**：`1c0706a5`（功能）、`6e51f96e`（剧场记录块）

## 改了什么

1. **退出剧场时往消息表插一条 `[剧场结束]`**（关闭播放 + 离开剧场 app 都发）
   - 内容：剧名集数 + 它这一场说过的原话（相邻去重、最多 5 句、每句掐到 42 字）+「现在回到主聊天了」
2. 剧场 app 的返回键接上 `leaveTheater`（收尾 + 真的走），不再裸跳

## 现象与病根（暮色 21:59 现场）

「最下面一条是我退出去又重新进时又刷了一条」。

他判断的病根是对的：**模型并不知道刚刚退出重进了**。

- 重连时 `boot()` 把库里剧场记录重新灌一遍 —— 这是**对的**，不灌模型就完全失忆
- 但灌进去的历史是「用户问 → 角色答 → 用户又问 →（没了）」，**最后一条是用户的话**
- 模型看到「我上一轮没回」，于是补一条 → 表现就是一进来它又自己说话
- 这就是 10-07 那个复读的滚雪球起点

**这一条 `[剧场结束]` 同时解决三件事**：

| 作用 | 怎么做到的 |
|---|---|
| 重进不再以为漏了回复 | 历史最后一条变成「结束了」，不是用户的话 |
| 主聊天知道刚才一起看了什么 | 这条带 `source: 'theater'`，进主聊天上下文 |
| 看得见、能删 | 落进剧场记录块（`TheaterRecordBlock`），主聊天最上面 |

## 踩坑 / 需要知道的（重要）

- ⚠️ **TDZ 差点又踩**：第一版把 `finishTheaterSession` 定义在 `closePlayback` **之后**，
  而 `closePlayback` 的依赖数组里写着它 → 运行时崩。而且那次编辑顺手把
  `closePlayback` 的定义整个吃掉了（只剩使用处），是 grep 发现「定义不见了」才逮到。
  **规矩：剧场这几个回调有严格的先后顺序**（`recordWatch` → `finishTheaterSession` → `closePlayback` → `leaveTheater`）。

- **存 `role: 'system'` + `[剧场结束]` 前缀**，照抄主聊天 `[系统: …]` 铃铛胶囊的惯例
  （`Chat.tsx` 的 `pushImageBedWarning`）。**别存 user 或 assistant** ——
  前者主聊天会以为是暮色说的话，后者会以为是角色自己说的。

- **内容用原话，不让模型再写一遍**。两个理由：零额外调用；而且这一场里
  **它对画面的描述本来就在这些话里**（10-07 截图原话：「画面显示女孩来到牢房看望链子上的男人」、
  「女孩在给男人喂汤，说她排了很久才买到的」）。原样带过去，主聊天的模型就知道它当时看见了什么。

- 收尾失败**不许挡住退出**：try/catch 里只 `diag()`，用户点返回不能因为写记录失败卡住。

- 「这一场」怎么界定：**上一条 `[剧场结束]` 之后的所有剧场消息**。
  连着看几集也算一场（用 `metadata.theaterEnd` 找分界）。

## 剧情串不起来 —— 10-07 的结论（还没动手）

暮色问「怎么能让它把剧情串起来」，截图里角色答得**完全正确**：

> 「这些是隔一阵送一次的画面，我只能照实说我看到的，中间发生的不清楚哦」
> 「这些画面是单独推送过来的，我只能看到眼下的」

**这不是模型的锅，是我们设计的**：抽帧每隔 N 秒送一张，中间那段它压根没收到。
提示词里第 1 条还明确写着「中间发生了什么你不知道」「绝对不要编剧情」——
它是在**照章办事**。

所以「让模型记住剧情」= **得有一份剧情流水账送进会话**，三档做法：

| 做法 | 成本 | 质量 | 说明 |
|---|---|---|---|
| A 现在这样（带它说过的原话） | 0 | 中 | 已有，但它只在**想说**的时候才描述画面 |
| B 每 N 秒让模型顺带写一句「刚刚发生了什么」 | 每 N 秒一次调用 | 高 | 最准，但打断沉浸、贵 |
| C 每集结束调一次，把关键帧（每 20s 抽一张，一集约 15 张）一起发过去写摘要 | 每集一次 | 最高 | 干净，跟「一起看完了」是同一次调用 |

**建议 C**，而且跟这次的 `[剧场结束]` 天然合在一起：退出剧场时一次调用，
既能写剧情摘要，又能带上它的看法。代价是每场多一次带图请求。
⚠️ **没动手**——等暮色拍板。
