# 手机端远程播放「电脑上的短剧库」完整方案

> 写给**要自己实现这套功能的 AI**。目标是让你少走我走的那些弯路。
> 场景：手机 App（https 页面 + Capacitor WebView）要能看/存**自己电脑上**的短剧库。

---

## 0. 一句话架构

```
手机 App ──http──▶ 转发服务(你的电脑) ──http+Cookie──▶ 短剧库(你的电脑)
         │                                                 │
         └── 局域网直连，不经过任何公网                        └── 下载目录（真文件在这）
```

**为什么必须有中间那层转发服务**（三条都实测撞过）：

| 问题 | 没有转发时 | 加了转发怎么解 |
|---|---|---|
| 混合内容 | 页面 https、资源 http，安卓内核对 `<video>` 单独拦混合内容，`allowMixedContent` 管不到 | 转发层用 `fetch` 取回来（能通），转成 blob URL 再喂 `<video>` |
| 跨站 | 短剧库有来源检查，手机的 Origin/Referer 一过去就被拒 | 转发层**剥掉** `origin`/`sec-fetch-site`/`referer`/`host`，换上自己的 viewer cookie |
| 跨站读不到自定义头 | 浏览器只让 JS 读 `Access-Control-Expose-Headers` 列过的头 | 转发层把这些头补全 |

**注意**：剥 Origin 这套白名单行为是短剧库自己的实现，**别去改它**，在转发层绕。

## 1. 两条数据通路，别混

| 通路 | 什么时候用 | 数据在哪 | 特点 |
|---|---|---|---|
| **在线播放** | 电脑上还没有这部 | 转发的 HTTP 流 | 边下边播，**占播放名额** |
| **本地播放 / 下载到手机** | 电脑上下好了 | 转发从硬盘读文件 | 原生支持 Range，**不占名额** |

判断某一集走哪条：

```js
const canPlayOnline = !!dramaId && online;        // 有剧 id + 连着电脑
const epState = (title, n) =>                      // 这一集实际在哪
  phoneHas(title, n) ? 'phone'                     // 手机里（断网可看）
  : macHas(title, n) ? 'mac'                       // 电脑里
  : 'none';                                        // 都没有 → 只能在线
```

**「文件在不在」和「能不能看」是两件事。** 集数格子不能因为「文件不在」就置灰——
它可能能在线播。灰格子看着就像点不动，用户直接不试了。

## 2. 在线播放链路

```
POST /api/ui/playback/open      {dramaId}          → {session, total}
GET  /api/ui/playback/stream    ?session&episode… → fMP4 字节流
POST /api/ui/playback/control   {session, action:"close"}   ← 必须还名额
```

### 2.1 拿流 + 挂播放器

```
fetch stream → ReadableStream → MediaSource
             → isTypeSupported(mime) 挑设备支持的
             → addSourceBuffer → 逐块 appendBuffer
             → URL.createObjectURL(mediaSource) → <video src=blob:…>
```

### 2.2 会话必须还回去（最容易翻车的地方）

短剧库的并发名额是**全机共享、总共很少**（我们是 4）。

- 切集、退页、App 被系统杀掉 —— 任何一条路径不 `close`，名额就一直占着
- 名额占满之后，**手机上和电脑网页版全都会 429**
- 闲置回收是分钟级，不是秒级；所以 App 里自己维护一份「开过的 session」账本，
  **每次进剧场先把它们全 close 一遍**

**首包看门狗**：源站拉不动时（红果续读 403/资源已变化），短剧库会**一直重试**，
而它重试期间**会话一直占着名额**。所以超过 N 秒还没收到第一个字节，就自己
`abort()` + `close` —— 宁可这一集失败，也不能把名额占死连累所有人。

## 3. 下载到手机链路

```
点「下载到手机」
  ├─ 选集（弹窗：区间 / 全选 / 全不选 / 体积估算）
  ├─ 电脑上还没这部 → POST /api/ui/download {ids:[dramaId]}（走短剧库任务队列，不占名额）
  └─ 每 1.2 秒问一次「磁盘上现在真有哪些集」
       └─ 新的、手机里还没有的 → 取那一个 → 下载到手机 → 下完再问下一集
```

**为什么不让手机直接从在线流下**：

- 在线流是「边转边送」，一集要实时流完才下完，比电脑直接拉源文件慢好几倍
- **它占播放名额** —— 名额才 4 个，拿它下载等于下载期间手机和电脑都看不了剧

所以：**电脑先下（后台队列），下完一集拷一集给手机**。这个中间步骤
**对用户完全不可见**——界面只有一个进度「已存进手机 x/N」。

### 3.1 大文件必须走原生下载，绝不能 base64

```ts
await Filesystem.downloadFile({ url, path, directory: Directory.Data, progress: true });
```

**别**用「fetch → ArrayBuffer → base64 → `Filesystem.writeFile`」。
Java 侧收到字符串后会**再拼一遍**，WebView 有 256 MB 上限，一集 74 MB 就穿顶：

```
java.lang.OutOfMemoryError: Failed to allocate a 74064696 byte allocation
  at com.getcapacitor.Bridge.callPluginMethod
```

## 4. ⚠️ 踩过的坑（这部分比上面的链路更重要）

### 4.1 🔴 系统的「已下载」标志会说谎 —— 一定要去数磁盘

我信了 `GET /api/ui/tasks` 里的 `playable: true`，结果：

```
短剧库说：咱家剑宗…第二季  666 集 全部 playable
磁盘实际：22 个 .mp4（外加 2 个 023.part.mp4 下到一半）
```

**644 个集是假的**。短剧库把「已排进队列」和「文件已落盘」混在同一个布尔标志里了。
`paused`（暂停）≠ 文件在。

照着假名单去下载 → 服务端从磁盘找不到文件 → 404 → 客户端一集报一次错，
**58 集全失败就是 58 条提示糊满屏**，底下要点的按钮全被盖住。

**修法**：加一个只读接口，直接数目录，并且**只认完整的 `NNN.mp4`**：

```python
for name in os.listdir(directory):
    m = re.match(r"^(\d{1,4})\.mp4$", name)   # 排掉 .part.mp4 和 .drama-id
    if m: episodes.append(int(m.group(1)))
```

拿到真值之后：格子着色、「下载到手机（N）」的 N、可选集列表、自动接续的判断，
**全部换用这份真值**。

> 教训：**判断「文件在不在」只能直接问文件系统。**
> 一个布尔标志不会报错，它只会让你拿着假名单去干真事，然后每一步都失败。

### 4.2 🔴 关掉「在线会话」不等于关掉「播放器」

```js
const closeOnline = () => {
  abort.abort();          // 断开取流
  closeSession(session);  // 还名额
};
```

这跟 `<video>` **一点关系都没有**。不拆播放器的话，旧视频继续拉、继续解码、
继续出声 —— 切剧时屏幕上还是上一部的内容。

**要拆两处，缺一不可**：

```jsx
{/* 1. 清地址 */}
setBlobUrl(old => { if (old) URL.revokeObjectURL(old); return ''; });

{/* 2. 重建元素 —— 只清地址不够 */}
<video key={src || '空'} src={src || undefined} />
```

为什么第 2 步不能省：React 只把同一个元素的 `src` 属性改成 `''`，
同一个元素还在，网络层和解码器都还挂着旧流。而且 `src=""` 在 Chromium 里
会把 currentSrc 落到**文档 URL** 上，反而多发一次没意义的请求。
`key` 一变，旧元素从 DOM 上摘掉，浏览器随即停掉它的一切。

### 4.3 🔴 同一个 bug 会藏在多个入口里

我们的症状是「点剧名进选集页，集数全点不动」。修好 `openEpisodes`（选集页那个入口）
之后，用户从「正在追剧 → 接着看」进去，还是同一个症状。

**因为「接着看」是直接跳播放页，压根不经过 `openEpisodes`**，补数据的逻辑一次都没跑。

修法：把那段抽成一个函数，**所有入口共用**：

```js
const resolveDramaId = (d) => d.id || (dramas.find(x => x.title === d.title)?.id) || d;
```

> 规则：**修「某处不生效」时，先数一遍有几种入口能到那儿。**
> 同一天栽了两次同一个坑：一次是三套判据只改一套，一次是两个入口只修一个。

### 4.4 🔴 跨站 JS 读不到自定义响应头

头确实过去了，`Access-Control-Expose-Headers` 里**没列**的，JS 就是读不到。
表现是「服务端明明发了这个头，客户端拿不到」，非常容易漏查。

```python
Access-Control-Expose-Headers: X-Playback-MIME, X-Playback-Source, X-Playback-Mode,
                               X-Playback-Quality, X-Playback-Run, X-Playback-Prefetched
```

### 4.5 ⚠️ 编解码要按设备挑，别兜底裸 mime

实测真机：

```js
MediaSource.isTypeSupported('video/mp4')                              // false
MediaSource.isTypeSupported('video/mp4; codecs="avc1.42C01F, mp4a.40.2"')  // true
```

所以：**先问服务端要编码串**（响应头里），**再问设备支不支持**，
两者都过了才 `addSourceBuffer`。不要在失败后兜底一个裸 `video/mp4`。

### 4.6 ⚠️ 下载接口不建父目录

```
Filesystem.downloadFile  → 不建父目录 → open ENOENT（一集都下不成）
Filesystem.writeFile     → 建（recursive: true）
Filesystem.mkdir         → 目录已存在时**照样 reject** → 状态栏红条
```

解法：**先用 `writeFile` 写一个 0 字节占位文件把目录顶出来**，下完删掉。

### 4.7 ⚠️ `error` 事件在安卓 WebView 上会误报

视频还没 ready 就可能抛 `error`。**延迟判定**：3 秒内 `canplay` 来了就当没发生。

### 4.8 ⚠️ 剧名/剧 id 是路径的一部分

短剧库的下载目录是按**剧名**分的（`短剧下载/<剧名>/001.mp4`），
所以剧名是路径参数，必须 `encodeURIComponent`，服务端要 `unquote`，
**并且要做目录穿越校验**（拒绝含 `/`、以 `.` 开头的）。

### 4.9 ⚠️ 剧库列表给的集数是假的

`episodeCount` 字段实测值是 `'1'`。可信度排序：

```
手机里真有的集数  >  下载任务里的 total  >  打开播放会话返回的 episodes.length
```

另外 `filter(t => t.dramaTitle)` **不会**让 TypeScript 收窄出 `string`，
要写类型守卫 `filter((x): x is string => !!x)`。

## 5. 构建脚本会骗你

```jsonc
// ❌ 只有转译，没有类型检查
"build": "vite build"
```

esbuild 只转译，**不检查作用域、不检查类型**。所以
「变量定义在一个当场执行的小函数里、外面却用了它」这种错能一路溜到真机上崩：

```
ReferenceError: mine is not defined
```

**建议**：

```jsonc
"typecheck": "tsc --noEmit -p tsconfig.json",
"typecheck:mymodule": "tsc --noEmit -p tsconfig.json 2>&1 | grep -E '^(src/mymodule|components/mymodule)'"
```

老项目往往有几百条历史类型错误，塞进 `build` 会立刻卡死。
所以：**全量只当参考，另外加一条只查你正在改的那几个文件的，退出码 0 = 干净**。
