# 剧场：没邀请就压根不接进来（补完昨天做的一半）+ 空回兜底写错导致「同一句话三遍」

**日期**：2026-10-07
**涉及 commit**：`956e8268`

## 改了什么

暮色 03:29 截图反馈两件事，一次修完。

### 一、邀请开关之前只做了一半

10-07 02:42 那轮实现的是「**不邀请就不喂画面和声音**」，
**连接照建、话照说、还在一直重连**。截图里没邀请，角色照样回了一堆
「我现在什么都看不见，也不知道演到了哪里」。

暮色要的逻辑是「点进去看时不接 API，邀请角色一起看时才接」。

现在的做法：

- 连接层：`if (!active || !invited)` → 关连接 + 清现场。**不邀请 = 没建过连接**
- `send()`：加守卫（`if (!invitedRef.current) return`）
- 界面：没邀请就不渲染聊天区，换成模块级的 `SoloWatching` 引导块
- 依赖数组：`invited` 显式写出来，不能只靠 `cfgKey` 那一层

### 二、同一句话连说三遍 + 后面跟一句「没收到回复」

这是我 02:52 加的空回兜底写错了，两个错叠在一起。

## 踩坑 / 需要知道的（重要）

### ⚠️ `send()` 里加守卫不是多余的 —— `LiveSession.send()` 会自己把连接建起来

`LiveSession.send()` 在没连上时走的是：

```ts
this.pendingInput.push(text);
if (!this.wantOpen) this.start();   // ← 这里会把连接建起来
```

所以**光改 effect 是不够的**：用户在不邀请的状态下发一条消息，
反而会把连接建起来，上一行的 `!invited` 守卫就白写了。

判定「该不该重发」的时候别忘了这条链路——**任何一个能触发 send 的入口，
在拒绝之前都得先确认「连接确实没建」**，不然「拒绝」只是把状态改回去了。

### ⚠️ 判「模型有没有回答过」不能用 `streamingId`

`onTurnComplete` 一收到就 `streamingId.current = ''`。
于是「模型已经答完了、只是答得快」的情况下，12 秒那个检查照样判定成空回，
紧跟着弹一句「没收到回复，点这里再试一次」——**答案明明就在屏幕上**。

改成独立的 `answeredAt`（收到字的时间戳，只增不减）。

**通用判据**：任何「这轮到底有没有产出」的判断，**不要复用「当前正在产出谁」的变量**——
后者的生命周期是「产出一个就清空」，前者要的是「这次有没有产出过」。

### ⚠️ 重发同一句 = 新的一轮对话 = 重复回答

重发在模型那边**不是「重试」，是「用户又说了一遍」**。它会对着同一句再答一次。
跟重连一叠就变成三遍（10-07 现场就是三遍）。

所以现在分开：

| 情况 | 做什么 |
|---|---|
| 发的时候**连接就是断的**（消息压根没送出去） | 8 秒后自动补发一次 |
| 连接是好的、模型收到了却没回答 | **不重发**，12 秒后只显示提示，让他自己点 |

原则：**补发只补「没送出去的东西」，不替模型再问一遍。**
暮色 02:52 说的「自动重试一次」在这里被收窄了——原因是重发会制造重复回答，
重复比空回更糟。这条是当场改的判断，不是漏做。

### ⚠️ 「没连的东西不用报状态」

没邀请的时候界面换成 `SoloWatching` 引导块，**没有**「重连中」「连上了吗」那类状态条。
既然压根没建连接，就没什么可报的——报了反而像出故障了。

## 备注

- `SoloWatching` 是**模块级**组件（写在组件函数体里会让每次渲染都重建组件类型，
  React 认定类型变了就整棵子树先卸载再挂载，AGENTS.md §4.3）
- 依赖数组里 `invited` 显式写出来：`cfgKey` 里虽然含了 `invited`，
  但依赖数组只写 `cfgKey` 的话，编译器不知道这里读了 `invited`。
  以后谁改了 cfgKey 的格式，这里就静默失效了——那种坑最难查。
- 诊断记录（`window.__liveDiag` / `__liveRaw` / `__liveMedia` / `__livePrompt`）继续留着，
  等真机验收过再清
