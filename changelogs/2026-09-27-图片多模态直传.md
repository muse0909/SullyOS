**日期**：2026-09-27  
**涉及 commit**：（待提交）

## 改了什么
- `useChatAI.ts` cleanedApiMessages：保留数组 content（含 image_url），不再丢弃图片
  - 之前：数组 content 一刀砍 → 主模型只看到文字 `[图片]` 或描述
  - 现在：数组直接保留 → OpenAI 协议主请求天然带 image_url 块，多模态模型直接看图
- `useChatAI.ts` Gemini 主请求体（line 1818 附近）：数组 content 转 Gemini parts
  - `text` → `{ text }`
  - `image_url` base64 → `{ inline_data: { mimeType, data } }`
  - `image_url` 外链 → `{ fileData: { fileUri, mimeType: 'image/*' } }`
  - 跟识图 API 那段 buildGeminiVisionBody 同款转换

## 动了哪些文件
- `hooks/useChatAI.ts` — 2 处（cleanedApiMessages + Gemini 主请求体）

## 踩坑 / 需要知道的（重要）
- **chatPrompts.ts 不动**：它已经做了"最新一条带图 / 历史降级文字"的判断（line 1260-1265），所以 cleanedApiMessages 保留数组天然只多带最新一条图
- **OpenAI 协议不用改**：baseReqBody.messages 直接拿 fullMessages（含 cleanedApiMessages），数组 content 天然是 OpenAI 多模态格式
- **buildEmotionEvalPrompt 已处理数组**（line 194-200）：所以情绪评估函数不会因为数组 content 报错
- **识别 API 调用条件没动**：配了识图 API 的用户暂时是"双调用"（识图 + 直传），行为不坏但费 token。第二步加 enableVisionApi 开关后会消除这个过渡态
- **图床流程没动**：handleImageSelect 写死 imgbb 上传，跟 imageBedUpload.ts 是两套独立逻辑，互不影响
