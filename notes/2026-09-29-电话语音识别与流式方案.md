## 1. 现状问题（重新确认一遍）

现在的通话流程是**严格串行**的：

```
你打字 → 等大模型把整段话想完 → 等整段文字回来
→ 等整段音频合成完 → 才开始播
```

从点"说"到它出声，1.5～2 秒空白。而且：

- **它说话时听不见你**（麦克风按钮只是显示/隐藏输入框，没有录音功能）
- **全项目没有任何录音代码**（`getUserMedia` / `MediaRecorder` 一次都没出现过）
- **Android 清单文件里没有麦克风权限**（`android/app/src/main/AndroidManifest.xml`）

---

## 2. ⚠️ 最重要的一个坑（影响方案设计）

**MiniMax 的语音识别接口不支持音频流式输入。**

官方文档写得很明确：*"不支持无容器的裸 PCM 数据"、"音频侧流式输入（请自己做静音检测来实现伪流式）"*。

也就是说，接口只接受**一整段录好的音频文件**，不能边说边往上传。

**这对体验意味着什么：**

豆包能做到"你停顿两秒它就知道你还没说完"，是因为它边听边判断。咱们做不到——只能等你说完 + 静音一小段，才知道该识别了。

所以第一阶段能到的是这个节奏：

```
你说话 → 本地实时显示字幕（不花钱，即时）
→ 你停下静音 600ms → 录的整段上传 → 拿回文字
→ 模型开始想 → 流式合成 → 边收边播
```

**实际体感延迟：800ms ～ 1.2 秒**（豆包是 300ms 内判停）。

比现在的打字框快一大截，接近真人打电话的节奏（真人接话本身也要 300～800ms），但**离豆包那种"抢话都能接住"还有距离**。

**如果想再压一点**，可以做"伪流式"：每 1.5 秒切一片上传一片，最后一片到的时候前面的早识别完了，文字直接拼起来。代价是断句可能不准。这个作为可选项，第一阶段先不做。

## 3. 阶段 0：语音识别底座（先做这个）

### 为什么先做识别

- 风险最高的一块（麦克风权限、原生权限、音频格式、跨域），先啃
- 识别通了，后面流式合成是纯增量，不用返工
- 就算后面不做了，单独一个"说话代替打字"也已经值了

### 做什么

1. **加麦克风权限**
   - `android/app/src/main/AndroidManifest.xml` 加录音权限声明
   - 首次进入通话页时弹权限申请
   - 被拒绝 → 降级回打字模式（**不崩，不卡死**）

2. **录音 + 音量检测**（新增 `utils/callVoice.ts`）
   - 用浏览器标准的录音接口，**不用**项目里那个媒体插件（它只能录完整文件，做不了实时音量判断）
   - 音频参数：**单声道、16 千赫兹**（官方建议，识别率不受影响，上传体积小一半）
   - 实时算音量，画成通话界面上的音量条
   - 静音超过 600 毫秒 → 认为你说完了 → 触发识别

3. **识别接口**（新增 `api/minimax/asr.ts`）
   - 照抄 `api/minimax/voice-clone.ts` 的写法（同款跨域处理、同款国内外分流）
   - 上传音频 → 调 `asr-1.0` → 返回文字
   - 走服务端代理的原因：文件上传不能像现在那样用 `minimaxFetch`（它只发 JSON，不支持传文件）

4. **界面改造**（改 `apps/CallApp.tsx`）
   - 底部麦克风按钮改成**按住说话**（或者点一下开始/点一下停）
   - 说话时显示**音量条**（本地实时算，零延迟）——注意：识别不是流式的，所以说话过程中**不可能**边说边出字
   - 松手 / 静音判定后上传，识别完才把文字显示出来，然后自动触发回复
   - **打字框保留**，随时可以切回去

5. **顺手修一个 bug**
   - `apps/CallApp.tsx:598` 读历史记录的音频地址，但保存时从没写过这个字段 → 通话记录详情页的"重播语音"按钮**从来没出现过**。一起修掉。

### 验收标准

- [ ] 第一次进通话页会弹麦克风权限，允许后能开始说话
- [ ] 说话时能看到自己的音量条在跳
- [ ] 停 0.6 秒后文字自动出现并发出，角色正常回话
- [ ] 拒绝麦克风权限时，能用打字继续聊，不崩
- [ ] 挂断后通话记录里正常显示，且详情页能重播语音
- [ ] 安卓真机 + 电脑网页预览都能用

### 会踩的坑（提前写下来）

1. **安卓 WebView 里录音要处理被系统打断**（来电、切后台）——要监听并暂停，不能崩
2. **静音阈值 600 毫秒是拍的**——太短会抢话，太长会显得迟钝。先给 600，实测再调
3. **识别失败要有兜底**——网络挂了、余额空了、超了 50MB 上限，都要给中文提示并能重试，不能卡在"在想……"
4. **长录音超限**：接口单次最多 500 秒 / 50MB，通话不会到，但还是要截断保护
5. **权限拒绝后不能死循环弹窗**——拒绝一次就记住，直接给"用打字"的按钮

## 4. 阶段 1：流式合成（阶段 0 稳了再动）

### 做什么

1. **大模型改流式输出**
   - 现在 `apps/CallApp.tsx:689` 是 `stream: false`，一次等全部文字
   - 改成流式，收到一段就送去做合成

2. **合成改网页连接的流式**（`wss://api.minimaxi.com/ws/v1/t2a_v2`）
   - 边收音频边播，不用等整段合成完
   - 现有 `utils/minimaxEndpoint.ts` 只支持 JSON 请求，要加一个网页连接通道

3. **提示词要改**（`apps/CallApp.tsx:317-323`）
   - 现在写的是"2-4 句就够了"（防止啰嗦）
   - 流式要改成"短句分段吐，一句说完再起下一句"
   - 这是改流式必须配套的，不改会串句

4. **换 turbo 模型**
   - 打电话时用 `speech-2.8-turbo`，省一半钱还更快
   - 聊天和见面继续用 hd，不受影响

### 预期收益

延迟从 800～1200ms 再压到 **400～700ms**。加上阶段 0 的自动发送，体验上是"说一句它就接一句"。

### 风险

- 串句：流式分段切错位置会出现半句。靠提示词约束 + 停顿标签来缓解，但不保证零
- 流式合成比一次性合成更容易触发限流，要留降级（流式失败自动回退到一次性）

## 5. 明确不在这次范围里的

- **打断**（它说话时你插嘴它立刻停）——这是阶段 2，最大的坑是回声消除（手机放的声音会被麦克风收回去），安卓上能做但不稳，要单独评估
- **背景音抗干扰**——这个靠识别模型自己，咱们控制不了
- **换主 API 做真·全双工**——代价太大，暂时不考虑
