# 剧场：海报「片名一闪一闪」的真正根因 + 控制条压到最上层

**日期**：2026-10-06
**涉及 commit**：`9fb00cb9`

## 改了什么

### 海报（三个原因叠在一起，之前两轮都没修对）

1. **六个渲染零件写在了 `TheaterApp` 函数体里** —— 这是主因。
   `TopBar` / `CoverImg` / `HoldItem` / `Grid` / `Empty` / `SectionCard`
   全是 `const X: React.FC = ...` 写在函数体内。每次渲染都造出**全新的函数对象**，
   React 认定「组件类型变了」，于是把整棵子树**先卸载再挂载** —— 网格里每一个
   `<img>` 都被销毁重建，所有海报重新加载一遍。
   已全部搬到模块级，主题色 `p` 和转发地址 `addr` 改成从 props 进来。

2. **转发服务给**所有**响应都盖了 `Cache-Control: no-store`** —— 这是放大器。
   `relay.py` 的 `pump()` 无条件补一条 `no-store`，把短剧库自己给的
   `private, max-age=86400`（海报能存一天）压掉了。响应里同时出现两条
   `Cache-Control`，浏览器按最严的那条办 → 手机一张海报都不留缓存。
   跟第 1 条叠加 = 每次重渲染都要把所有海报重新走一遍网络。
   已改成：只有 `/api/ui/playback/stream` 和 `/api/ui/playback/prefetch`
   强制 `no-store`，其它资源沿用上游自己给的。

3. **`CoverImg` 把 alt 文字设成了片名** —— 这是「闪」的直接来源。
   图片还没加载完的那一瞬间，浏览器内核会把 `alt` 文字画在图片框里，
   而 alt 传的正好是剧名 —— 所以看到的就是「片名在海报位置一闪一闪」。
   已改成：占位图标铺在下面、图片盖在上面（不再是二选一渲染），`alt` 传空串
   （片名就在下面的 `h3` 里，重复一遍没意义）。加载期间看到的是图标，一个字都不闪。

## 踩坑 / 需要知道的（重要）

- **「组件写在函数体里」是 React 里最容易犯又最难发现的坑之一。**
  它不报错，`npm run build` 也拦不住（esbuild 只转译不检查），类型检查更查不出
  —— 因为类型签名完全合法。表现只是「界面上有点闪」「图加载慢」，
  很容易被误判成网络问题、图片格式问题、缓存问题，然后一路修错地方。
  症状是**整个子树反复重挂**，凡是列表里带 `<img>` 的页面都会中招。
  **判据**：`grep -n "^  const X: React.FC" 组件文件` —— 有输出就说明写错地方了。

- **`alt` 文字会被内核画进图片框。** 图片没加载完 / 加载失败时，
  `alt` 的内容会出现在那个图片框里（尺寸不够就换行）。所以
  **不要把「用户能读懂的文案」塞进 alt**，特别是当它会闪的时候。
  装饰性图片一律 `alt=""`，旁边有可见文案就更好。

- **不要在 React 事件里直接改 DOM 样式**（`e.currentTarget.style.xxx = ...`）。
  React 不知道你改了，重渲染时也不会还原，状态和 DOM 就对不上了。
  原 `onError` 里的 `style.display = 'none'` 就是「偶尔闪出来一下」的来源。
  要改状态就 `setState`。

- **失败状态要记「是哪个地址失败」，不是「失败过没有」。**
  记布尔量的话，换剧 / 换源时新地址会被上一张的失败连坐判死。
  `const [badSrc, setBadSrc] = useState(''); const failed = !!src && badSrc === src;`

- **转发层不要无条件覆盖上游的 `Cache-Control`。**
  多条同名响应头浏览器按最严的办，无条件补 `no-store` 等于把上游所有的缓存
  优化全部作废 —— 而且**症状不是「图裂了」，是「图永远在重新加载」**，
  会被误判成渲染 bug。判断缓存有没有生效要直接看响应头。
