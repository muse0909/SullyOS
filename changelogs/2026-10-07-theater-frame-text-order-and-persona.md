## 踩坑 / 需要知道的（重要）

### ⚠️ 病根不在措辞，在**发法**

答非所问和没人设看着是两件事，其实是同一个：

抽帧循环每 1.2 秒以 `role: 'user'` 的身份发一句「（背景画面：正在播到第 X 分 X 秒）」。
对模型来说，那就是**用户一直在说话，而且一直在报进度**。于是：

```
user:（背景画面：正在播到第 3 分 04 秒）
user:（背景画面：正在播到第 3 分 05 秒）
user:（背景画面：正在播到第 3 分 06 秒）
user:阿九好看吗          ← 真正问的那句，夹在中间
user:（背景画面：正在播到第 3 分 07 秒）
```

- **答非所问** —— 他那句话不是最后到达的，模型按规矩回最后那句 → 回的是刚跳过去的那一帧。
- **没人设像旁白** —— 对话里绝大多数是「背景画面」轮次，模型的隐含任务已经变成「解说这部剧」，人设自然掉光。

修法：那句话不再单独成轮，只**攒着**（`bgNote`）。用户开口时拼成**同一个 turn 的两个 part**：

```
[{ text: '（背景：这会儿在播第 3 分 07 秒…这是背景资料，不用回。）' }, { text: '阿九好看吗' }]
```

背景在前、问的话在**整个请求的最后**。顺序由这一次发出去决定，后面再怎么抽帧都插不到它前面。

**教训**：给实时模型喂「持续发生的事」（画面、声音、环境音）时，**别把它包装成对话轮次**。
每 1.2 秒一条 user 消息 = 每 1.2 秒告诉模型「对方在跟你说话」。

### ⚠️ 「核心指令后面就没了」这个怀疑可以排除

暮色问「如果带了是刚开始带了后面就没了？还是每一轮都带了？」

**带了，而且一直都在。** `buildSetup()` 里的 `systemInstruction` 是建会话时发一次、
整个会话期间**持续生效** —— 服务端在关掉连接之前一直拿着它。不存在「后面就没了」。

内容是 `ContextBuilder.buildCoreContext()`：身份、核心指令、自我领悟、世界观、世界书、
用户画像、私密印象、记忆库、记忆宫殿、角色备忘录、情绪底色，全套。

真机想验的话读 `window.__livePrompt`（有 `chars` / `heads` / `hasWorldbook` 等字段）。

### ⚠️ `typecheck:theater` 漏了 `hooks/useTheaterLive.ts`

`see is not defined` 能一路走到手机上，根子在这：

```json
"typecheck:theater": "... | grep -E '^(apps/TheaterApp|components/dramaTheater|utils/dramaTheater)'"
```

`hooks/useTheaterLive.ts` 不在里面。而**这一条恰恰是唯一能拦住它的检查**（TS2304）。

**build 拦不住它**（esbuild 只转译不查作用域），**typecheck:theater 也拦不住它**（范围没覆盖），
所以它一路走到手机上才炸。已把 `hooks/useTheaterLive` 加进 grep 范围。

**顺着这条推广**：改 `typecheck:theater` 的覆盖范围时，要对着「这次改动实际动了哪些文件」核一遍，
别只按 AGENTS.md 里写的旧清单来。这次的教训是 —— **清单会过期，忘了更新的清单比没有更危险**
（它给人「已经查过了」的错觉）。

### ⚠️ 库里的 id 是数字，`TheaterMsg.id` 声明的是 string

`boot()` 里读历史往 `TheaterMsg` 灌时直接塞 `m.id`（number）→ TS2322。
真机跑没事，但这条常驻报错会把真正新冒出来的错一起淹掉（`grep` 出来的永远有它）。
统一 `String(m.id)`。
