# 剧场：播放器改悬浮窗 —— 竖版小、键盘白边、全屏按钮不管用是同一个病根

**日期**：2026-10-07
**涉及 commit**：`9d943548`

## 改了什么

暮色 13:58 报的三个显示问题 + 15:26 拍板的悬浮窗方案。

### 三个问题其实是同一个病

原来的容器这么算：

```
宽度撑满 → 除以视频比例 = 高度 → 再加一句「最高不超过 42vh / 影院 64vh」
```

**宽度不是自己定的，是被高度倒推出来的。** 于是同一个根因三种表现：

| 表现 | 机制 |
|---|---|
| 竖版剧画面特别小 + 周围全是空白 | 比例 0.56，354 × 0.56 ≈ 200px 宽，容器缩成 200 居中，两侧露**页面白底** |
| 横版剧好好的 | 比例 1.78，354 × 1.78 = 630 > 手机宽度，「高度上限」用不上，宽度照旧撑满 |
| 输入框一弹就出现白边 | 软键盘让可视屏高变小 → 上限变小 → **连横版剧**都被压窄 |
| 全屏按钮「不管用」 | 横版剧 42% 和 64% 算出来都超过手机宽度 → 画面**一点变化都没有** |

### 改成悬浮窗

暮色 15:26 定的方案：**背景是全屏聊天页，播放器浮在上面，比例不变、大小只调宽度、
位置随便拖**。这套算法里没有「高度倒推宽度」，上面四种表现一起消失。

- 三档宽度 48% / 70% / 92% 屏宽，高度 = 宽度 ÷ 比例
- 存档存**中心点**（不是左上角）—— 切档时四周对称缩，不往一个方向跳
- **长按 320ms 或挪动 8px = 拖动**，否则算点按
- 点按 = 只显隐工具条（**不再兼播放/暂停**，暮色 15:26 同意）
- 上下两条工具条一起显一起藏，3 秒
  - 上面 = 导航：剧名 / 下一集 / 大小 / 选集（**选集放最右，大小挨着选集**）
  - 下面 = 播放：进度条 / 播放 / 时间 / 音量 / 全屏
  - 小档（190px 宽）下面那条只留 播放 / 音量 / 全屏，上面那条压成三个小圆钮
- 避开输入框（暮色选的 **B**）：底部留 118px，拖动和存档都会夹
- 全屏：铺满 `inset-0` + `object-contain`，**只留黑边不裁画面**

## 踩坑 / 需要知道的（重要）

### ⚠️ 全屏和浮窗必须复用同一个 DOM 节点

全屏和浮窗是**同一个 div 的同一套 style**，只改值不换节点。

换成分支渲染（`{full ? <A/> : <B/>}`）的话，即使 `key={src}` 相同，父节点一换
video 还是会被重建 —— 而声音采集走的是 `createMediaElementSource(video)`，
**同一个 video 元素只能接一次，接第二次直接抛异常**。换节点 = 声音当场断掉，
且**没有任何报错**，表现是「画面在动但角色听不见了」。

这也是为什么根 div 上没有任何条件渲染包着 video。

### ⚠️ 切集后角色听不见声音（顺手修的既有 bug）

`audioTap.attach` 原来写的是：

```ts
if (this.attached) return true;   // 接上过一次就永远说「接好了」
```

但**切集会让 video 整个重建**（PlayerStage 里 `key={src}`，为了让旧画面别继续播）。
于是新一集的元素**从来没被接过**，`attached` 却还是真 —— 采到的是已销毁的旧元素。

改成判「是不是**同一个元素**」：

```ts
if (this.attached && this.el === el) return true;
if (this.attached) this.teardown();   // 旧链彻底拆掉再接新的
```

**⚠️ 反过来写会炸**：不能写成「先无条件 detach 再 attach」——
`createMediaElementSource` 对**同一个元素**只能调一次，第二次直接抛。
**换元素是安全的**（一个元素一个 SourceNode），不安全的是重复接同一个。
所以判据必须是「是不是同一个元素」，不是「有没有接过」。

### ⚠️ 存档存中心点，不存左上角

切档时宽度会变。存左上角的话，从「大」切到「小」会往左跳一大截；
存中心点则四周对称地缩，放着不动才符合直觉。

### ⚠️ `clampCenter` 里 min > max 的情况

浮窗比可用高度还高时，`minCy > maxCy`。`Math.min(Math.max(v, min), max)`
遇到 min > max 会静默给出 min，看着对其实每次重渲染都在跳。
所以显式用 `Math.min(minX, vw/2)` / `Math.max(minCx, ...)` 兜住。

### ⚠️ 竖屏大档在小屏手机上比可用高度还高 → **收窄，不截断**

截断会破坏比例（暮色：「可以有黑边，但要保证画面全部显示出来」）。
收窄只是那一档在小屏上没那么大，**比例一点不变**。

### ⚠️ Tailwind 两个类谁后生效说不准

工具条的公共外观里原本带 `pt-2 pb-8`，小窗分支又要 `pt-1 pb-6`。
Tailwind 生成的 CSS 顺序**不是**按 className 字符串顺序来的，表现是
「小窗的条子边距莫名其妙」。现在 padding 由每个分支自己写完整，冲突消失。

### ⚠️ 键盘弹起要重新夹位置

安卓 WebView 弹键盘会触发 `resize`，可视高度少三四十个百分点。
不重新夹的话浮窗停在旧位置，正好压在被顶上来的输入框底下，用户不知道为什么。
防抖 120ms 再算（键盘弹起是连着来好几帧的）。
